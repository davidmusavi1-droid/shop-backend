# بازطراحی پنل مدیریت MOTIF — دستور دوم

وضعیت: آماده بررسی در شاخهٔ مجزا؛ بدون انتشار یا تغییر اطلاعات فروشگاه اصلی.

## بررسی مبنا

مبنا کامیت `d9d02b5` از main است؛ دستور اول در PR #20 ادغام شده است. پنل قبلی در `public/admin.html`، ویرایشگر عکس در `admin-images.js` و مدیریت صفحهٔ اصلی در `admin-site.js` بودند. APIهای واقعی `/api/products/admin/list`، POST `/api/products`، PATCH `/api/products/:id` و POST `/api/uploads/images` استفاده می‌شوند. ورود با `X-Admin-Token` و بررسی امن سمت سرور حفظ شده است. توکن در حافظهٔ صفحه می‌ماند.

خواندن عمومی API سایت در این اجرا دو محصول و وجود فیلدهای جدید دستور اول را تأیید کرد. دستهٔ قدیمی و دستهٔ خالی محصولات به‌صورت خودکار تغییر نکردند. مشاهده عمومی، جایگزین بررسی محصولات خصوصی و پایگاه دادهٔ کامل نیست.

هیچ migration یا مدل دادهٔ موازی اضافه نشده؛ هیچ محصول، عکس، گرید، قیمت یا موجودی واقعی تغییر نکرده است.

## صفحات و قابلیت‌ها

| صفحه | نتیجه |
| --- | --- |
| ورود | فرم فارسی، پیام واقعی خطای احراز هویت، توکن فقط در حافظه |
| داشبورد | پنج آمار از خروجی API مدیریتی، عملیات سریع، محصولات اخیر |
| ثبت محصول | تنها مسیر ثبت، پنج مرحله، اندازه‌های وابسته به نوع، قیمت سه‌رقمی، بررسی نهایی و تأیید جداگانه انتشار |
| ویرایش | یک صفحه با ۹ بخش باز و بسته‌شونده، دسترسی مستقیم به قیمت/موجودی، هشدار خروج و حفظ شناسه متغیرها |
| فهرست | نام/کد/برند/SKU، دسته، گرید، وضعیت، نقص، مرتب‌سازی و صفحه‌بندی ۲۰تایی |
| تنظیمات | مدیریت موجود صفحهٔ اصلی، رنگ‌ها، بنرها، فونت‌ها و نسخه‌های قبلی حفظ شده است |
| تصاویر | چندانتخابی، پیش‌نمایش، جایگزینی، ترتیب، تصویر اصلی، حذف تأییدشده، خطای دقیق و تلاش مجدد |

موبایل: منوی پایین با چهار مقصد؛ دسکتاپ: ستون کناری. فضای پایین فرم و صفحه برای منو در نظر گرفته شده است. فونت محلی وزیرمتن با مجوز موجود پروژه استفاده می‌شود؛ سرویس فونت یا وابستگی اجرایی خارجی اضافه نشده است.

قیمت/موجودی، کیفیت و تصاویر متغیرها در بخش مربوط نمایش داده می‌شوند؛ کنترل‌ها به ردیف و شناسهٔ متغیر اولیه متصل می‌مانند. فیلدهای مخفی اندازه پاک نمی‌شوند. تغییر گروه بالاتنه/شلوار با اندازهٔ موجود، هشدار می‌دهد.

عکس‌های ایراد محصول و هر متغیر مستقل‌اند. گریدها خودکار تغییر نمی‌کنند؛ گرید متفاوت متغیر حفظ می‌شود. وجود عکس قبلی باعث ناپدید شدن دسترسی به آن نمی‌شود. نام فایل MOTIF با کد عددی ناسازگار رد می‌شود. خروجی پردازش قبلی تصویر، WebP و حداکثر ۳٬۰۰۰٬۰۰۰ بایت است؛ JPG و PNG ورودی پشتیبانی می‌شوند. حذف مرجع، شیء ذخیره‌شده را پاک نمی‌کند.

## پیش‌نویس، انتشار و بازیابی

پیش‌نویس همان `isActive=false` موجود است؛ دادهٔ نیمه‌کاره با کد یکتا و ردیف موجودی معتبر قابل ذخیره است. عنوان و رنگ پیش‌نویس می‌توانند خالی بمانند؛ عنوان نمایشی «پیش‌نویس بدون نام» در داده ذخیره نمی‌شود. SKU، اعداد معتبر و قیود یکپارچگی همچنان الزامی‌اند.

ناقص بودن از اطلاعات فعلی محاسبه می‌شود. آماده بررسی یعنی پیش‌نویس فاقد نقص ضروری؛ وضعیت مستقل پایگاه داده نیست. آمار ناقص می‌تواند شامل کالای قبلاً منتشرشده باشد. دو محصول موجود به‌دلیل نقص جدید، خودکار از انتشار خارج نمی‌شوند.

انتشار جدید نیازمند خلاصه نهایی و تأیید dialog است. درخواست UI دارای `publicationIntent=true` است و سمت سرور نیز بررسی می‌شود. فعال‌سازی مجدد پیش‌نویس، حتی بدون این پرچم، از بررسی کامل بودن عبور می‌کند. ویرایش عادی کالای قدیمیِ فعال با قواعد سازگار قبلی انجام می‌شود؛ برای حفظ سازگاری، ساخت اولیه از مشتری‌های API قدیمی همچنان قواعد قبلی POST را دارد.

بازیابی خودکار فرم در sessionStorage همان زبانه، با کلید وابسته به هش حساب و بدون ذخیرهٔ توکن است. خروج صریح، نسخه بازیابی را پاک می‌کند. این قابلیت به HTTPS وابسته است و نسخهٔ پشتیبان دائمی نیست؛ بسته شدن زبانه می‌تواند آن را از بین ببرد. فایل آپلودنشده بین بارگذاری مجدد قابل بازیابی نیست؛ نشانی عکس‌های موفق در فرم حفظ می‌شود. ذخیرهٔ خودکار شبکه‌ای و انتشار خودکار انجام نمی‌شود.

پس از پاسخ نامعلوم POST، کد یکتا در فهرست سرور تطبیق داده می‌شود؛ در صورت پیدا شدن، همان محصول باز می‌شود. قید یکتایی پایگاه داده و کنترل updatedAt / expectedStock حفظ شده‌اند. تغییرات هم‌زمان با خطای تعارض رد می‌شوند.

## آزمون‌ها

- `npm test`: ۶۲ آزمون موفق؛ شامل کنترل انتشار، پیش‌نویس واقعاً ناقص، حفظ داده، یکتایی، موجودی، آپلود HTTP، مجوز و محدودیت تصویر.
- `CHROME_BIN=... node test/admin-browser.cjs`: موفق؛ سه دسته، ثبت پنج‌مرحله‌ای، تأیید انتشار، ویرایش و حفظ گرید/عکس/شناسه، شکست و تکرار آپلود، جایگزینی/ترتیب، بازیابی فرم، چندسایزی و جلوگیری از POST تکراری پس از گم شدن پاسخ.
- مرورگر در عرض‌های ۳۶۰، ۳۹۰، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ بررسی شده؛ بدون پیمایش افقی در فهرست.
- آزمون‌های مرورگر `structure-browser.cjs`، `upload-browser.cjs`، `content-browser.cjs`، `storefront.cjs` و `measurement-browser.cjs` نیز اجرا شده‌اند. این آزمون‌ها از API آزمایشی استفاده می‌کنند؛ آزمون سطل واقعی لیارا نیستند.
- مسیرهای قبلی آزمون یکپارچه برای ناوبری جدید به‌روزرسانی شدند. اجرای PostgreSQL و migration/restore در گردش CI موجود انجام می‌شود؛ نتیجهٔ آن باید پیش از ادغام بررسی شود.

## محدودیت‌ها و شرط انتشار

1. API فعلی فقط آرایه نشانی عکس دارد و نقش مستقل Label/Front/Back/Detail ندارد. راهنما، ترتیب و عکس اصلی پیاده شده‌اند؛ ذخیرهٔ مستقل این نقش‌ها انجام نشده و به تصمیم جداگانه دربارهٔ مدل موجود نیاز دارد. فیلد موازی ساخته نشده است.
2. فهرست از API مدیریتی موجود همهٔ محصولات را می‌گیرد و صفحه‌بندی/فیلتر در مرورگر است. برای آرشیو بسیار بزرگ، صفحه‌بندی سمت سرور مرحلهٔ بعدی است.
3. تست مرورگر اتصال واقعی لیارا، دستگاه Samsung A23 و اینترنت اپراتور را تأیید نمی‌کند. پیش از انتشار یک آزمون واقعی در محیط غیرتولیدی لازم است.
4. تصاویر تحویلی پیش‌نمایش‌اند؛ پنل جدید هنوز روی دامنه اصلی قرار نگرفته است.

انتشار پس از بررسی PR، عبور CI، آزمون واقعی ورود/ذخیره/آپلود در محیط جداگانه، و تأیید نهایی مالک انجام شود. نسخه قبلی کد برای بازگشت نگه داشته شود؛ تغییری در طرح پایگاه داده برای این بازطراحی لازم نیست.

## آزمون واقعی هنگام انتشار تأییدشده

`verify-admin-release.cjs` با مسیرهای واقعی HTTP، توکن موجود محیط و طرح موقت تصادفی `motif_admin_smoke_<hex>` آزمون می‌کند. Prisma فقط روی همین schema موقت اجرا می‌شود؛ در پایان schema آزمایشی پاک می‌شود. هیچ تغییری روی رکوردهای فروشگاه انجام نمی‌شود و هش همه محصولات/متغیرهای واقعی پیش و پس از آزمون مقایسه می‌شود. ورودی JPG و PNG در حالت واقعی روی فضای فعلی لیارا آپلود و نسخه WebP قابل دریافت بررسی می‌شوند؛ دو شیء بسیار کوچک آزمایشی بدون اتصال به محصولات فروشگاه باقی می‌مانند. هیچ کلید یا نشانی اتصال در گزارش چاپ نمی‌شود.

گردش CI همین آزمون را با `--skip-storage` و PostgreSQL موقت اجرا می‌کند. برای انتشار واقعی، تنها آرشیو آماده‌شده می‌تواند فایل `.motif-admin-release-check` داشته باشد؛ هوک `liara_pre_start.sh` پیش از شروع سرویس، آزمون را اجرا می‌کند و پس از موفقیت، پرچم را برمی‌دارد. نبود پرچم، رفتار شروع عادی را حفظ می‌کند. شکست آزمون، شروع نسخه جدید را متوقف می‌کند. پرچم حاوی هیچ اطلاعات حساسی نیست.
